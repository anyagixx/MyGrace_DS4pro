# MyGRACE Instructions for Aider

This project uses MyGRACE (Graph-RAG Anchored Code Engineering) — a scalable methodology for large AI-driven projects.

## Critical Rule: Lazy Navigation
- Start with `docs/graph-index.xml` (≤100 lines) — always read this first
- Then read specific `docs/modules/M-XXX.xml` files (30-80 lines each)
- Never scan all module files at once
- No monolithic XML files exist — use index + per-entity pattern

## Six Principles
1. MODULE_CONTRACT before code — define PURPOSE, SCOPE, DEPENDS, LINKS
2. START_BLOCK/END_BLOCK are navigation anchors, not comments
3. graph-index.xml is always current
4. Top-down: Requirements → Technology → Plan → Verification → Contracts → Code
5. Verification is architecture — tests, traces, logs are blueprint
6. Governed autonomy — freedom in HOW, not in WHAT

## Project Structure
docs/graph-index.xml (module index)
docs/plan-index.xml (phase index)
docs/verification-index.xml (verification index)
docs/modules/ (per-module M-XXX.xml files)
docs/plans/ (per-phase Phase-N.xml files)
docs/verification/ (per-verification V-M-XXX.xml files)

## File Conventions
Each source file has:
- MODULE_CONTRACT comment block
- MODULE_MAP of symbols
- CHANGE_SUMMARY of recent changes
- START_BLOCK/END_BLOCK pairs for code sections

## When editing
- Preserve MODULE_CONTRACT, MODULE_MAP, CHANGE_SUMMARY
- Preserve START_BLOCK/END_BLOCK boundaries
- Update CHANGE_SUMMARY after changes
- Update graph-index.xml if module interfaces change
